# InputMore 主浮窗体验优化设计

## 1. 背景与目标

当前主浮窗已经支持 rawWrite、enhance、translate 和 ask 的入口，但不同状态的尺寸、间距和操作层级不一致。设置窗口也存在长页面滚动问题，但本次只处理主浮窗主链路，设置页另立任务。

本次目标：

- 去掉初始态的音符和 `InputMore` 品牌文字，减少装饰性内容；
- 使用 `READY` 作为左侧状态锚点；
- 将文本、翻译、检索统一为圆形图标 + 竖排中文标签按钮；
- 明确鼠标悬停和键盘焦点反馈；
- 统一输入态、处理中、结果态的尺寸约束，避免内容溢出；
- 不改变现有能力、Provider、Flow 或检索行为。

## 2. 视觉基线

主浮窗使用深色半透明胶囊、暖灰/深棕色背景、暖白文字和暖灰描边。交互反馈不引入蓝灰色或其他新强调色：

- 默认：按钮使用现有半透明暖灰/深棕色；
- 鼠标悬停：只提亮当前按钮，使用同一色系的更亮版本；
- 键盘焦点：沿用悬停的提亮背景，并增加清晰的暖白或暖灰外轮廓；
- 不使用渐变，不因为状态变化改变布局尺寸；
- 其他按钮保持不变，避免整条浮窗产生跳动。

按钮使用统一的最小点击区域和间距。图标只表达功能，不使用音符等装饰性占位图形：

- 文本：文档/文本图标；
- 翻译：语言转换图标；
- 检索：放大镜图标；
- 设置：独立分隔线后的齿轮图标。

## 3. 状态与布局

### 3.1 空闲态

```text
READY | [文本图标 文本] [翻译图标 翻译] [检索图标 检索] | 设置
```

空闲态保持图 3 的视觉比例：`READY` 必须完整显示且不可被 flex 压缩；三个能力入口使用圆形按钮，图标在上、中文标签在下。`READY` 是状态信息，不表示某个能力已经选中。功能按钮只在鼠标悬停或键盘焦点时提亮。

录音态使用动态声音纹：波形柱以不同高度和节奏循环变化，左侧显示波形，右侧显示 `REC`。录音动画在 `prefers-reduced-motion: reduce` 下停用，但仍保留静态波形。

### 3.2 输入态

```text
标题/能力名                                      取消
┌──────────────────────────────────────────────┐
│ 输入内容                                     │
└──────────────────────────────────────────────┘
翻译时：目标语言选择       Ctrl+Enter 提交     主操作
```

输入态使用统一面板骨架：标题栏、输入区、可选配置行和操作行。翻译保留目标语言选择；文本和检索不显示无关控件。主操作按钮与取消按钮保持稳定位置，避免因文案变化发生横向跳动。

### 3.3 处理中

展示能力标题、处理中状态和可取消操作。处理中不允许旧请求的结果覆盖当前界面；取消后回到空闲态或上一个明确的预览状态。

### 3.4 结果/预览态

结果区域使用可滚动容器，长文本不能撑破浮窗。翻译默认只预览，不自动写回；检索继续展示答案和来源，插入仍由用户主动触发。rawWrite 和 enhance 维持现有写回规则。

### 3.5 错误态

在同一面板中展示简短、可理解的错误文案，并提供重试和关闭/取消操作。错误内容不得泄露 API Key、Provider 原始响应或内部堆栈。

## 4. 尺寸与溢出约束

- 浮窗宽度保持适合桌面边缘停靠的固定基准，并允许内容态使用更高高度；
- 所有面板使用 `box-sizing: border-box`；
- 输入区、结果区和来源区必须设置明确的最大高度与 `overflow: auto`；
- 文本、按钮和选择器不得依赖绝对定位互相覆盖；
- 窗口尺寸变化由状态驱动，状态切换完成后再调整窗口，不让内容先渲染到旧尺寸中；
- 内容超出时优先滚动内容区，不滚动整个胶囊边框；
- 长语言名称、长错误文案和长结果必须能够换行或截断，不得产生横向溢出。

## 5. 架构边界

本次改动限制在 presentation 层及其必要的样式/测试连接：

- 不把 Provider 调用放进 UI；
- 不修改 TranslationService、RetrievalService、LlmProvider 或 SearchProvider；
- 不改变 translationFlow、retrievalFlow、rawWrite 和 enhance 的业务语义；
- 如果需要补充状态展示字段，先通过现有 SessionState/SessionEvent 明确定义，再补状态机回归测试；
- `App.tsx` 只做必要的页面组合和事件转发，不继续增加业务编排。

## 6. 测试设计

### Presentation

- 空闲态正确展示 `READY`、三个图标文字入口和设置入口；
- `READY` 完整展示，不出现 `REA...` 或被按钮挤压；
- 音符和 `InputMore` 不再渲染；
- 录音态展示动态声音纹和 `REC`，减弱动效偏好下不执行动画；
- 悬停只提亮当前按钮；
- 键盘焦点只提亮当前按钮并显示焦点轮廓；
- 输入态在翻译/文本/检索之间显示正确控件；
- 取消、空输入、长文本、长语言名和长错误文案不产生溢出；
- 结果区域可滚动，浮窗尺寸不被长内容撑破。

### Application/回归

- 保留已有翻译预览、取消和旧请求丢弃测试；
- 保留 rawWrite、enhance 和 ask 的原有回归测试；
- 不添加真实 Provider/API Key 依赖；
- 运行相关 Vitest、完整 Vitest、`npm run build` 和 Rust 检查。

## 7. 非目标

- 本次不重构设置页；
- 本次不继续实现检索 Agent 或 Firecrawl 流程；
- 本次不支持自定义 Prompt；
- 本次不更换 Provider，不调整 API 配置模型；
- 本次不修改翻译、检索或文本处理的业务规则。
