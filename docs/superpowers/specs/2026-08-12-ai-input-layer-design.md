# AI 输入增强层：交互与架构设计

## 1. 产品定位

产品是一个模型无关的桌面 AI 输入增强层，优先服务开发者和 AI 重度用户，长期扩展为通用桌面输入层。

MVP 的默认体验不是通用 AI 助手，而是：

> 用户说话，系统优化转写，并把结果写回当前输入框。

产品借鉴 Typeless 的系统级快捷键、低打扰浮窗和跨应用写回方式，但保留可切换 Provider 的模型层。

## 2. MVP 入口边界

产品只保留三个入口：

| 入口 | 目的 | 默认输出 |
|---|---|---|
| 默认快捷键 | 优化语音转写 | 直接写回当前输入框 |
| 翻译快捷键 | 明确的语言转换 | 直接写回当前输入框 |
| Ask 快捷键 | 提问、必要时检索 | 在浮窗展示，不自动写回 |

默认入口暂不承担键盘文本自动改写、Prompt 自动改写、总结、扩写或问答。

文本输入仍然支持，但主要用于特殊入口：用户可以在翻译或 Ask 浮窗中键入、粘贴或录音。用户只是普通打字时，直接使用当前应用自身的输入框。

## 3. 默认入口：优化转写

主流程：

```text
默认快捷键 → 录音 → 语音识别 → 优化转写 → 写回当前输入框
```

优化转写允许：

- 去除口头禅和明显重复；
- 自动断句和补充标点；
- 修正明显语病；
- 保留原意、事实和语气强度；
- 根据当前应用进行轻度格式适配。

优化转写不应：

- 擅自总结、扩写或改变事实；
- 自动改造成 Prompt；
- 自动回答问题或调用搜索；
- 过度改变语气、立场或内容结构。

系统可以优化“怎么说”，不能未经触发改变“要做什么”。

## 4. 特殊入口

### 翻译

用户通过专用快捷键或明确表达“翻译成某语言”触发。目标语言必须明确；如果无法确定，不猜测，提示用户补充。翻译默认写回当前输入框。

### Ask

Ask 合并问答与检索。用户不需要区分“问答”和“搜索”；系统根据问题是否需要实时信息、用户是否明确要求搜索、是否要求来源等条件，决定直接回答或调用检索工具。

Ask 默认在浮窗展示答案，不自动写回。用户可以点击“插入答案”后写回。MVP 只保留当前浮窗会话上下文，不建立完整聊天历史。

## 5. 用户可感知状态机

```text
空闲
  → 唤起
  → 待输入 / 录音中
  → 转录中
  → 处理中
  → 写回或展示结果
  → 完成
```

### 空闲

应用驻留后台，监听全局快捷键。

### 唤起

浮窗立即出现，显示产品已启动、当前 Action 和录音提示。默认入口直接进入录音；特殊入口进入可录音、键入或粘贴的输入状态。

### 录音中

显示录音指示、简化波形或音量反馈、录音时长和停止提示。用户再次按键或释放长按结束录音，Esc 放弃。

### 转录中 / 处理中

显示“正在识别”“正在整理”“正在生成”等简短阶段提示。超过阈值后显示仍在处理，并允许取消。Provider、模型名称和内部路由细节不进入主反馈。

### 结果处理

- 默认优化转写：直接插入光标位置或替换选中文本；
- 翻译：直接插入或替换；
- Ask：浮窗展示，提供复制、插入和继续提问。

### 完成

写回成功后短暂显示“已写入”和“撤回”入口，随后浮窗自动消失。用户可以重新按快捷键开始下一次操作。

### 失败

保留原始输入和生成结果，提供重试、改为键入、复制原文、复制结果、打开设置或取消等操作。内容不能因错误被静默丢弃。

## 6. 快捷键与窗口行为

- 默认快捷键：启动优化转写；录音中再次按键停止；处理中取消；
- 翻译和 Ask 使用独立快捷键；
- Esc 在所有活动状态优先表示取消；
- 浮窗唤起时获得焦点；写回前保存原活动应用、窗口、选中文本和光标上下文；
- 写回后重新激活原应用；
- 浮窗置顶但不长期抢占焦点；
- 待输入、录音中、处理中和失败状态不因点击外部而意外关闭；
- 成功状态短暂显示后自动关闭；
- 浮窗优先显示在光标附近，其次是活动窗口下方，再以屏幕底部中央兜底。

## 7. 写回与撤回

写回前保存操作快照：

```text
目标应用、目标窗口、光标位置、原选中文本、生成结果、操作时间
```

- 无选中文本：在光标处插入；
- 有选中文本：替换选中文本；
- 无法可靠确认目标位置：自动复制结果，不覆盖当前内容；
- 写回成功：提供短时间撤回；
- 用户已继续编辑导致无法安全撤回：明确提示，不强行恢复。

## 8. 模型层

所有文本功能使用同一个用户配置的活动 Provider 和模型，不在 MVP 中按意图路由不同模型。

上层只调用统一变换接口：

```text
TextTransformer.transform(request, active_model) -> result
```

Provider 通过统一适配器接入：

```text
OpenAIProvider
AnthropicProvider
GeminiProvider
DeepSeekProvider
QwenProvider
OpenAICompatibleProvider
LocalProvider
```

第一版优先支持文本生成统一接口和独立语音转录接口。Provider 失败时默认重试一次；自动切换备用 Provider 默认关闭，避免用户无法预期数据流向和费用。

## 9. 权限与隐私

按需申请权限：首次录音时请求麦克风权限，首次写回时请求辅助功能权限。权限说明必须明确用途。模型调用使用用户配置的 Provider；第一版不默认建立云端历史记录，撤回所需的临时数据仅短暂保留。

## 10. MVP 范围

必须实现：

- Windows 桌面驻留和全局快捷键；
- 默认语音录入；
- 语音转写与轻度优化；
- 翻译入口；
- Ask 入口的基础回答；
- 一个统一模型 Provider 接口；
- OpenAI-compatible API 配置；
- 浮窗状态反馈；
- 跨应用写回、剪贴板兜底和撤回；
- 麦克风、辅助功能和网络异常恢复。

暂不实现：

- 默认入口的键盘文本自动改写；
- 自动 Prompt 改写；
- 复杂多模型路由；
- 完整聊天历史；
- 多轮 Agent；
- 默认联网检索；
- 直接复用 ChatGPT Plus 或 Claude Pro 订阅权益。

## 11. 设计原则

1. 默认入口降低表达成本，不增加模式选择。
2. 默认入口只做优化转写，特殊任务显式触发。
3. 只有用户已有内容的任务默认写回；产生新信息的 Ask 默认展示。
4. 功能依赖模型能力接口，不依赖具体厂商。
5. 不确定时采用最小变换，不擅自改变任务类型。
6. 失败时保留内容并提供恢复路径。
